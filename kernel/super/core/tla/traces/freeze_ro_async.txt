Layout: b freezes through a block device; A is an error handler that sets SB_RDONLY

          that never took the rwsems (L2279-2287).

The filesystem is SB_UNFROZEN with the three percpu rwsems write-held for good:
every sb_start_write()/sb_start_pagefault()/sb_start_intwrite() sleeps
uninterruptibly from now on (mnt_want_write() calls sb_start_write() before it
checks for read-only, so even a write that should fail with -EROFS hangs), a
later read-write remount hangs every writer, and the next freeze blocks forever
in percpu_down_write().  The same happens when the error comes after
SB_FREEZE_COMPLETE (the model finds both).  ext4 stopped setting SB_RDONLY on
errors for exactly this (d3476f3dad4a).  Trigger: FIFREEZE on jfs or nilfs2
(errors=remount-ro by default), a read that hits corruption, FITHAW.
