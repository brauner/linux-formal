freeze_wake_nobarrier -- NoLostWakeup violated -- mutation SBW_BARRIER off (what keeps wait_for_partially_frozen() safe without smp_mb() before wake_up_var())

Layout: u (FIFREEZE) and b (block device) freeze concurrently; stores to
s_writers.frozen are buffered (WEAK_WAKE) and, as a mutation, percpu_down_write() is
not a full barrier.

 2-5   u  freeze_super(): SB_FREEZE_WRITE, s_umount dropped, the WRITE rwsem.
 6-8   b  freeze_super() sees SB_FREEZE_WRITE: wait_for_partially_frozen() L2060 samples
          old = WRITE (L2065) and drops s_umount (L2067) -- the task is delayed before
          it queues itself.
 9-15  u  retakes s_umount, stores PAGEFAULT, FS, COMPLETE; without the barrier these
          stores are all still in u's store buffer.
 16    u  wake_up_var() (L2332): waitqueue_active() sees nobody -- b is not queued yet.
 17    b  prepare_to_wait_event() queues b, reads frozen: still WRITE (the stores are
          buffered) == old: b sleeps.
 18       u's stores drain.  b sleeps with its condition true and no wakeup coming.

In the kernel this cannot happen: the PAGEFAULT store is followed by
percpu_down_write()'s atomic_xchg() (kernel/locking/percpu-rwsem.c L89), so a
waiter that still reads WRITE was queued before u's later wake_up_var() looks at
the queue, and a waiter reading any later value does not sleep (it only ever
waits with old == WRITE).  freeze_wake_weak and freeze_all_weak pass with the
kernel's barriers.
